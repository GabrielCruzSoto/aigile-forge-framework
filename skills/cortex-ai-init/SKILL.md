# Skill: Cortex-AI Project & Team Namespace Initialization

## Purpose & Activation

Activate only when `aff.yaml` sets `knowledge.mode: cortex-ai` and a user or onboarding workflow requests initializing external Cortex-AI second-brain indexing for a project (`cortex-ai init`, `initialize cortex`). If `knowledge.mode` is `local` or `folder-sync`, skip this skill and inform the user how `knowledge.mode` is currently configured.

## Inputs

- `aff.yaml` fields: `project.name`, `project.slug`, `team.name`, `knowledge.cortex.drive_root_id`, and `knowledge.cortex.notebook_id` (if pre-existing).
- Active MCP connections for Google Drive, NotebookLM, and optional Engram persistent memory (`capabilities.mode: mcp`).
- Local `knowledge/` seed files generated by `./aigile init`.

## Decision Gates

| Condition | Action |
|-----------|--------|
| `knowledge.mode != cortex-ai` in `aff.yaml` | Stop; report current `knowledge.mode` and do not call external MCP tools |
| Drive or NotebookLM MCP server unavailable | Stop cleanly; report offline MCP server and keep local `knowledge/` intact |
| Remote project folder + valid `README.md` already exist | Run idempotently: verify NotebookLM link, repair missing metadata if needed, do not duplicate folders |
| `knowledge.cortex.drive_root_id` missing in `aff.yaml` | Search for root `CORTEX-AI` folder or prompt user to confirm root folder creation |

## Step-by-Step Execution

### 1. Normalize Namespace Slugs
1. Normalize `team-slug` and `project-slug` to lowercase kebab-case.
2. Resolve target hierarchy: `CORTEX-AI/{team-slug}/{project-slug}` when a team namespace is configured, or `CORTEX-AI/{project-slug}` for standalone projects.

### 2. Provision Idempotent Drive Hierarchy
1. Resolve the configured `knowledge.cortex.drive_root_id` from `aff.yaml` (using placeholder/configured project values only — never hardcoded third-party IDs).
2. Check whether `{team-slug}` and `{project-slug}` folders already exist before creating them so repeated runs never create duplicate folders.
3. Generate and upload a canonical registry `README.md` inside `{project-slug}` containing:
   - `project_slug`, `team_slug`, `created_at` (ISO-8601 UTC)
   - Repository topology and active stack profiles from `aff.yaml`
   - Linked NotebookLM `notebook_id`

### 3. Initialize NotebookLM Knowledge Brain
1. Create (or attach existing) NotebookLM notebook titled `CORTEX-AI — {team-slug}/{project-slug}`.
2. Seed initial sanitized architecture and domain documents from `knowledge/` (`domain-glossary.md`, `system-landscape.md`, `roster-and-ways-of-working.md`).

### 4. Persist Cross-References Locally & in Engram
1. Update `aff.yaml` (`knowledge.cortex.project_folder_id`, `knowledge.cortex.notebook_id`) using non-secret resource identifiers.
2. When Engram MCP is active, call `mem_save` with topic key `cortex-ai/project/{project-slug}` (`type: config`, `capture_prompt: false`) storing the Drive folder reference, NotebookLM notebook ID, and initial sync timestamp.

## Hard Rules & Guardrails

- **Idempotency First**: Always list parent folder children before creating folders or notebooks.
- **Zero Secrets Uploaded**: Run `./aigile secret-scan` on `knowledge/` before uploading any seed document to Drive or NotebookLM.
- **Graceful Degradation**: Never fabricate Drive URLs or NotebookLM IDs if MCP calls fail or run in `zero-mcp` environments.

## Outputs

- Provisioned remote `CORTEX-AI/{team-slug}/{project-slug}` folder with registry `README.md`.
- Indexed NotebookLM notebook seeded with `knowledge/` baseline docs.
- Updated `aff.yaml` `knowledge.cortex` metadata and Engram cross-reference entry.

## Verification Checklist

- [ ] `aff.yaml` confirms `knowledge.mode: cortex-ai` prior to external MCP calls.
- [ ] `./aigile secret-scan` passes on all seed documents before upload.
- [ ] Re-running initialization detects the existing folder/notebook without creating duplicates.
